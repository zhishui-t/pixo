## 1. 项目定位

Pixo 是一个以**自研渲染引擎和视觉感知为底座、由 DSH Agent 统一调度的智能修图系统**。系统不是固定流水线，而是具备反馈能力的修图智能体：

- 持续获取图片的结构化视觉事实。
- 根据事实进行量化决策。
- 通过渲染引擎执行修改。
- 再次测量，判断是否达标。
- 将不确定、不可自动修复的样本转入人工复核。

核心产出不是"一键修好"，而是**可解释、可追溯、可回归、可人工接管**的修图结果。

---

## 2. 设计原则

1. **视觉感知是唯一像素事实入口**  
   上层不直接看图，统一通过 Pixo Vision 获取结构化测量结果。

2. **元数据是辅助事实来源**  
   Pixo Meta 提供拍摄时间、地点、相机参数等先验信息，辅助决策但不能替代视觉测量。

3. **渲染引擎必须可测量**  
   渲染引擎输出成品的同时，还必须输出当前参数下的像素、区域统计和中间结果。

4. **硬规则与软知识分离**  
   - 硬规则：曝光公式、参数边界、终止条件、降级策略，固化在代码/配置中。  
   - 软知识：风格卡片、修图经验、场景策略，放在知识层。

5. **LLM 不猜测精确参数**  
   Agent 做语义理解、任务规划、风格推荐、异常解释；精确参数由量化决策层计算。

6. **用户显式意图优先级最高**  
   用户指定参数、风格、场景语义时，覆盖智能体推荐。

7. **审美判断不完全自动化**  
   审美分仅作参考，最终风格由用户或人工复核决定。

8. **所有过程可回溯**  
   每个参数、每轮迭代、每次降级都记录来源和原因。

## 5. 视觉模块设计（Pixo Vision）

### 5.1 定位

Pixo Vision 是系统的**硬事实来源**，只输出确定性强、可回归的测量数据。它不包含语义理解、不包含 LLM。

### 5.2 架构

```
Pixo Vision
├── 分割器
│   └── YOLOE-26L-seg（开放词汇实例分割）
│       输入：渲染后图像 + 文本提示
│       输出：人脸/人体/天空/植物等 mask
│       隔离：通过 Segmenter 接口封装，后续可替换
├── 测量器
│   ├── 基于 mask 提取区域像素
│   ├── 计算平均 Lab、亮度、溢出比例、对比度
│   ├── 输出置信度与可靠性标记
│   └── 输出结构化测量数据
└── 美学评分器
    └── Aesthetic Scorer（7维评分）
        输入：图像
        输出：各维度分数（0-5）
        用途：只写入 Trace 和复核队列排序依据，不进入决策输入
```

### 5.3 模型清单

| 模型 | 用途 | 许可 | 状态 |
|------|------|------|------|
| YOLOE-26L-seg | 开放词汇分割（人脸/人体/天空/植物） | AGPL-3.0 | ✅ 内部使用，技术债务记录 |
| Aesthetic Scorer | 7维美学评分 | MIT | ✅ 已接入，延迟 0.5-1s |
| DSH 主会话 | 视觉理解、语义判断、诊断建议 | - | ✅ 天然存在，Agent 层能力 |

**技术债务**：YOLOE-26L-seg 使用 AGPL-3.0 许可，产品化前必须解决（替换模型或购买商业授权）。已通过 `Segmenter` 接口隔离，详见第 16 节。

### 5.4 Pixo Vision 输出

```json
{
  "image_id": "DSC_5722",
  "render_version": "v3",
  "detection_version": "yoloe26l_seg_v1",
  "regions": {
    "face": {
      "mask_id": "face_0",
      "confidence": 0.87,
      "area_ratio": 0.03,
      "reliable": true,
      "mean_lab": {"L": 65, "a": 18, "b": 22},
      "mean_luminance": 118
    },
    "sky": {
      "mask_id": "sky_0",
      "confidence": 0.92,
      "area_ratio": 0.20,
      "reliable": true,
      "mean_lab": {"L": 80, "a": 2, "b": -10},
      "highlight_clip_ratio": 0.01
    }
  },
  "global": {
    "mean_luminance": 112,
    "highlight_clip_ratio": 0.004,
    "preview_highlight_clip_estimate": 0.003,
    "shadow_clip_ratio": 0.02,
    "contrast": 0.24
  },
  "aesthetic_scores": {
    "overall": 3.8,
    "quality": 4.1,
    "composition": 3.9,
    "lighting": 4.2,
    "color": 3.7,
    "depth_of_field": 3.5,
    "content": 3.6
  }
}
```

**可靠性规则**：
- 置信度 < 0.6 或面积占比 < 0.5% 时，`reliable` 设为 `false`。
- 决策层跳过不可靠区域的相关规则。
- 若不可靠区域覆盖关键目标（如人脸不可靠导致曝光规则无输入），Pixo Decide 直接输出 `manual_review`，不依赖 Agent 判断。

**preview 溢出率估计**：
- 全分辨率下，`highlight_clip_ratio` 按像素阈值精确计算。
- preview 下，使用 3×3 邻域最大值池化近似保留极值，避免下采样低估高光裁切。
- 当 preview 估算值 ≥ 2.5%（全分辨率阈值 3% 留 0.5% 缓冲）时，触发曝光方向限幅（见 9.4）。

### 5.5 接口

```python
class PixoVision:
    def segment(self, image, prompts: list[str]) -> dict[str, np.ndarray]:
        """分割，返回 mask 字典"""

    def measure_region(self, image, mask, metrics: list[str]) -> dict:
        """区域测量，返回带置信度的测量结果"""

    def aesthetic_score(self, image) -> dict:
        """美学评分（仅用于Trace和复核排序，不进入决策）"""
```

## 6. 元数据模块设计（Pixo Meta）

### 6.1 定位

Pixo Meta 负责**解析、标准化、存储、查询**图像元数据。它是系统的辅助事实来源，与 Pixo Vision 并列，不能替代视觉测量，但能在测量之前提供先验，减少盲猜。

### 6.2 职责

- 从 RAW/JPEG 中提取完整 EXIF。
- 标准化字段命名（不同相机厂商字段不一致）。
- 输出结构化元数据报告。
- 为 Agent 提供场景推断上下文。
- 为 Pixo Decide 提供摄影参数事实。
- 为 Pixo Know 查询提供索引键（如相机型号、镜头型号）。
- 连拍分组（基于时间间隔和图像内容）。

### 6.3 输出结构

```json
{
  "image_id": "DSC_5722",
  "camera": {
    "make": "NIKON",
    "model": "Z 6",
    "lens": "NIKKOR Z 50mm f/1.8 S",
    "serial_number": "6012345"
  },
  "capture": {
    "datetime": "2026-08-18T17:32:45Z",
    "timezone_offset": "+08:00",
    "gps": {"lat": 31.2304, "lon": 121.4737, "altitude": 4.5},
    "orientation": 1
  },
  "exposure": {
    "aperture": "f/1.8",
    "shutter_speed": "1/500",
    "iso": 100,
    "exposure_compensation": 0.0,
    "metering_mode": "matrix",
    "flash": "off"
  },
  "white_balance": {
    "as_shot": "auto",
    "temperature": 5200,
    "tint": 0
  },
  "shot_context": {
    "burst_group": "BURST_001",
    "shot_index": 3,
    "total_shots_in_group": 5
  }
}
```

### 6.4 元数据参与决策的规则

| 元数据 | 决策影响 |
|--------|----------|
| ISO ≥ 3200 | 降噪强度目标提高 |
| 场景为夜景 | 曝光目标区间调整（主体亮度 100-120 而非 110-130） |
| 快门 < 1/60 | 运动模糊风险高，锐化保守 |
| 白平衡 as-shot 为 Auto | 偏色诊断时优先怀疑白平衡 |
| 闪光灯开启 | 光源复杂度高，肤色目标区间放宽 |

### 6.5 接口

```python
class PixoMeta:
    def extract(self, raw_path) -> dict:
        """从 RAW/JPEG 提取完整元数据"""

    def infer_lighting_context(self, meta: dict) -> dict:
        """基于时间+GPS推断光照场景"""

    def detect_burst_groups(self, image_list: list) -> list[dict]:
        """基于时间间隔和内容识别连拍组"""
```

### 6.6 隐私与可靠性

- GPS 隐私：提供剥离 GPS 的选项。
- 数据缺失：不是所有图像都有完整 EXIF，系统必须能优雅处理缺失字段。
- 不可靠的元数据：时区可能错误、GPS 精度可能差，任何依赖元数据的决策都需要有 fallback。
- 用户意图优先：用户说"这是婚礼照片"应覆盖元数据推断的场景。

## 7. 渲染引擎设计（Pixo Render）

### 7.1 定位

自研渲染引擎，基础色彩已与线性 DNG 对齐。可独立运行，不依赖 Adobe 运行时。

### 7.2 已实现功能

| 模块 | 状态 | 说明 |
|------|------|------|
| RAW 解码 | ✅ | 黑/白电平、CFA 插值 |
| 白平衡 | ✅ | As Shot / 手动色温色调 |
| DCP 应用 | ✅ | ColorMatrix / ForwardMatrix / HueSatMap / LookTable |
| 构图（裁剪/旋转） | ⚠️ 需前置改造 | 原在管线末端，需移至 DCP 后、影调前 |
| 曝光 EV | ✅ | 线性空间 |
| 高光/阴影 | ✅ | 软压缩 |
| 曲线 | ✅ | RGB 亮度曲线 |
| HSL | ✅ | 分色调整 |
| 色彩校准 | ✅ | 全局色彩矩阵微调 |
| 色调分离 | ✅ | 高光/阴影独立调整 |
| 清晰度/去朦胧 | ✅ | 局部对比度 |
| 锐化/降噪 | ✅ | 输出前处理 |

### 7.3 管线顺序

```
RAW解码 → 白平衡 → DCP → 构图（裁剪/旋转） → 曝光 → 高光/阴影 → 曲线
→ 色彩校准 → HSL → 色调分离 → 清晰度/去朦胧
→ 降噪 → 锐化 → 输出
```

**构图前置的原因**：
- 构图改变画面内容，主体位置、天空面积都会变。
- 先构图再调整，确保所有调整都作用于最终画面。
- 避免先调整后裁剪导致测量区域失效。

**构图前置的技术要求**：
- 旋转 + 裁剪使用 Lanczos3 或更优插值。
- 插值在 DCP 色彩转换前的线性空间进行。
- 插值误差可能被后续色彩模块放大，需通过金样本集验证。

**构图前置验收标准**：

| 场景 | 验收标准 |
|------|----------|
| 纯裁剪/翻转（无旋转） | 像素级差异 ≤ 1e-4（数学上应完全一致，超标说明有 bug） |
| 含旋转 | 统计指标：PSNR ≥ 60dB 或平均色差 ΔE < 0.5 |

等价测试：同尺寸同位置旋转后对比，排除尺寸变化干扰。

### 7.4 裁剪参数结构

```json
{
  "crop": {
    "mode": "ratio",
    "ratio": "3:2",
    "center": [0.5, 0.5],
    "rotation": 0.0,
    "horizontal_flip": false,
    "vertical_flip": false
  }
}
```

或自由裁剪：

```json
{
  "crop": {
    "mode": "free",
    "x": 100,
    "y": 80,
    "width": 3000,
    "height": 2000
  }
}
```

### 7.5 接口

```python
class PixoRender:
    def render(self, raw_path, params) -> np.ndarray:
        """全分辨率渲染，返回构图后、影调调整后的图像"""

    def render_preview(self, raw_path, params, max_edge=1024) -> np.ndarray:
        """低分辨率预览，跳过降噪/锐化"""

    def get_linear_rgb(self, raw_path, params) -> np.ndarray:
        """获取线性RGB（构图后）"""

    def get_region_pixels(self, image, mask) -> np.ndarray:
        """获取区域像素"""
```

## 8. Agent 层设计（Pixo Agent）

### 8.1 定位

DSH 主会话作为 Agent，具备**原生视觉能力**，能直接看图。负责：

- 任务规划与流程编排
- 工具调用（Pixo Vision / Pixo Meta / Pixo Render / Pixo Decide / Pixo Know）
- 状态管理
- 异常处理与降级

### 8.2 Agent 与 Pixo Decide 的权责边界

**核心规则**：

- **Pixo Decide 是唯一终止判断来源**。它输出：达标 / 继续 / 降级 / 转人工。
- **Agent 只能**：
  - 同意 Decide 的终止判断，进入下一阶段。
  - 升级到人工复核（`AGENT_ESCALATED`），需记录理由。
- **Agent 不能否决** Decide 的客观达标判断。如果 Agent 认为硬指标不够好，只能升级，不能强行继续迭代。
- 状态机需支持从任意迭代状态到 `MANUAL_REVIEW` 的转移。

### 8.3 工具调用

| 工具 | 用途 |
|------|------|
| `pixo.vision.segment` | 获取区域 mask |
| `pixo.vision.measure` | 获取区域测量数据 |
| `pixo.vision.aesthetic` | 获取美学评分（仅Trace/复核） |
| `pixo.meta.extract` | 获取元数据 |
| `pixo.meta.infer_context` | 场景推断 |
| `pixo.render.render` | 执行全分辨率渲染 |
| `pixo.render.preview` | 快速预览渲染 |
| `pixo.decide.decide` | 计算参数调整，输出终止判断 |
| `pixo.know.query` | 查询知识 |

### 8.4 连拍选帧中的 Agent 角色

连拍选帧采用三层过滤：

1. **硬过滤**（Pixo Vision）：模糊、过曝、闭眼等客观指标淘汰废片。
2. **美学预筛**（Aesthetic Scorer）：对剩余照片打分，排序参考。
3. **语义优选**（Agent）：对前 3-5 张做表情、姿态、眼神等语义判断，输出推荐和理由。

Agent 输出必须带 `confidence`，低置信度时建议转人工，不替用户做唯一决定。

**连拍分组依赖 Pixo Meta**：通过拍摄时间间隔（如 < 2 秒）自动识别连拍组。

## 9. 量化决策层（Pixo Decide）

### 9.1 职责

确定性参数计算与终止判断。

### 9.2 输入

- Pixo Vision 的结构化测量结果（包含置信度和可靠性标记）
- Pixo Meta 的元数据报告
- 当前任务类型
- 用户硬约束与软偏好
- 知识层策略建议

**参数优先级链**（从高到低）：

```
用户锁定参数 > 用户软偏好 > 风格卡片目标 > 系统默认目标
```

冲突时，高优先级直接覆盖低优先级；同一优先级内冲突按规则 `priority` 字段排序。

### 9.3 输出

```json
{
  "decision": "adjust_and_continue",
  "params": {
    "Exposure": 0.28,
    "Highlights": -20,
    "Shadows": 10
  },
  "reasons": [
    "face_luminance 95 < target 115",
    "highlight_clip 0.4% within safe range"
  ],
  "rule_ids": [
    "exposure_rule_001",
    "highlight_protect_rule_002"
  ],
  "unreliable_regions": []
}
```

当关键区域不可靠时：

```json
{
  "decision": "manual_review",
  "unreliable_regions": ["face"],
  "reason": "face region unreliable, exposure rule cannot execute"
}
```

### 9.4 规则 schema 与冲突处理

规则配置示例（YAML）：

```yaml
rule_id: exposure_rule_001
priority: 10
condition:
  metric: face_luminance
  op: lt
  value: 110
action:
  param: exposure_ev              # 唯一参数，冲突判定依据
  formula: "2.2 * log2(target / current)"
  clamp: [-0.5, 0.5]
  step_decay: 0.5                 # 幂次衰减
  conflict_policy: "high_priority_wins"
```

**关键语义**：

- **冲突判定**：两条规则的 `action.param` 相同才构成冲突，高优先级胜出。
- **不同 param**：并行生效，非冲突。
- **step_decay**：`applied_fraction = step_decay^(iteration - 1)`。第 1 轮 100%，第 2 轮 50%，第 3 轮 25%。
- **收敛特性**：衰减导致改善量自然下降，可能提前触发"连续两轮改善低于阈值"终止条件，这是**预期行为**（快速收敛），非 bug。

**曝光方向限幅**：

- 当 preview 溢出率估计 ≥ 2.5% 时，Exposure 参数只允许负向修正或保持，不允许正向增加。
- 其他规则照常执行，不整体停摆。
- 决策输出仍为 `adjust_and_continue`，但 Exposure 的 clamp 上限临时设为当前值。

### 9.5 终止条件

满足任一即停止：

1. 所有目标指标进入容差范围。
2. 达到最大迭代轮数（3轮）。
3. 连续两轮改善量低于阈值。
4. 出现不可修复信号。
5. 用户锁定参数导致无法达标，转人工。

**迭代测量策略**：
- 迭代使用 preview 渲染（最长边 1024，跳过降噪/锐化）。
- 最终 QC 使用全分辨率渲染。
- 溢出率只在全分辨率下精确测量；preview 用邻域最大值池化估计。

### 9.6 回退处理

- FINAL_QC 若发现高光溢出率超标（> 3%），允许回退一次到 `COLOR_CORRECTING` 或 `EXPOSURE_ALIGNING`。
- 回退时强制将 Exposure 降低 **-0.15 EV**（规则 ID：`qc_rollback_rule`），写入 Trace，来源为 `quantitative_decision`。
- 若用户锁定了 Exposure，则跳过回退，直接转 `MANUAL_REVIEW`，理由为用户锁定导致无法修正。
- 回退计数上限为 1，第二次 QC 仍超标，转 `MANUAL_REVIEW`。

## 11. 状态管理（Pixo State）

### 11.1 状态机

```
RAW_PENDING → SCREENED → BASE_RENDERED → EXPOSURE_ALIGNING
→ COLOR_CORRECTING → STYLE_APPLIED → FINAL_QC
→ ACCEPTED / MANUAL_REVIEW / REJECTED
```

**补充转移**：

| 转移 | 条件 | 说明 |
|------|------|------|
| 任意迭代状态 → MANUAL_REVIEW | Agent 升级 | 标记为 `AGENT_ESCALATED` |
| FINAL_QC → COLOR_CORRECTING / EXPOSURE_ALIGNING | QC 超标且未回退过 | 回退限一次 |
| FINAL_QC → MANUAL_REVIEW | QC 第二次超标 | 不再自动修正 |
| FINAL_QC → ACCEPTED | 达标 | 进入验收 |
| FINAL_QC → REJECTED | 用户拒绝 | 明确废弃 |

## 12. 闭环工作流

### 12.1 单张修图闭环

```
输入照片
→ Pixo Meta 提取元数据
→ Agent 直接看图，结合元数据理解场景
→ 构图（裁剪/旋转）作为渲染参数确定
→ 调用 Pixo Vision 做硬感知（分割 + 测量）
→ 废片筛查
→ 基础渲染（preview）
→ 循环：
    Pixo Vision 测量（基于 preview 渲染结果）
  → Pixo Decide 计算参数，输出终止判断
  → 如果 continue：Pixo Render 执行（preview）
  → 如果 stop：进入最终 QC
  → Agent 只可同意或升级人工，不可否决
→ 最终 QC（全分辨率渲染 + 全分辨率测量）
→ 达标：验收 / 人工复核 / 拒绝
→ 超标：回退一次（限一次），或转人工
```

### 12.2 批量流程

```
批量输入 → Pixo Meta 提取元数据 → Agent 意图解析
→ Pixo Meta 连拍分组 → Pixo Vision 批量初筛
→ 过滤废片 → 逐张进入闭环
→ 输出成片 + 报告 + 复核队列
```

## 14. 评测体系

### 14.1 金样本集

- 20 张曝光异常照片
- 10 张肤色偏色人像
- 10 张逆光/夜景/顺光场景
- 10 组连拍
- 人工标注技术合格线或目标处理结果
- 记录 mask 边界参考，用于分割精度验证（阶段 3）
- 包含不同相机型号、镜头、ISO 的组合

### 14.2 技术指标

| 指标 | 目标 |
|------|------|
| 曝光修正后主体亮度 | 110–130 |
| 高光溢出 | < 3% |
| 暗部裁切 | < 2% |
| 肤色 b | 16–22 |
| 单张迭代轮数 | ≤ 3 |
| 不可自动修复率 | < 5% |

### 14.3 性能预算（初期）

| 指标 | 目标 |
|------|------|
| 单张端到端耗时 | ≤ 30 秒 |
| 批量处理吞吐 | ≥ 2 张/分钟 |

阶段 2 结束后实测，若超标则启动优化。

### 14.4 回归原则

任何规则、模型、参数边界调整都需跑金样本集，技术指标不退化才能合入。测量需锁定 `render_version` 与 `detection_version` 组合。

## 17. 风险与对策

| 风险 | 等级 | 应对 |
|------|------|------|
| 渲染引擎模块未验证 | 高 | 零调整回归 + 模块级测试 |

| DNG SDK 代码合规 | 高 | Clean-room 重写，产品化前完成 |

| 视觉测量不稳 | 中 | 版本控制 + 金样本回归 + 置信度 |
| 元数据缺失或错误 | 中 | 优雅降级，fallback 到视觉测量 |
| Agent 语义判断不稳定 | 中 | 硬规则固化在决策层，Agent 仅辅助 |
| 决策层规则复杂 | 中 | 规则配置文件化，优先级+覆盖策略 |
